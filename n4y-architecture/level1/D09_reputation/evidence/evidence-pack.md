## Source Conflicts and Notes

1. **Score scale divergence**: Mnemom (E10) uses 0–1000 scale; ERC-8004 (E1, E18) uses 0–100 (uint8). The two can coexist via normalization (ERC-8004 as on-chain anchor, Mnemom as off-chain detailed scoring). Related to OI-043 (open issue on score scale).

2. **Static vs adaptive weighting**: Mnemom (E10) uses fixed weights; TrustFlow (E11) and FedAWA use adaptive/learned weights. No conflict — different maturity levels. Logos architecture can start with static weights (interpretable) and evolve to adaptive.

3. **Sybil resistance philosophy**: MeritRank (E17) states Sybil resistance is fundamentally impossible in trustless systems (reputation trilemma); TrustFlow (E11) claims max 4pp impact from Sybil attacks. These are compatible — MeritRank addresses theoretical impossibility of *full* resistance while TrustFlow demonstrates *practical* tolerance.

4. **GDPR vs blockchain immutability**: E20 (Zylos) identifies that cross-platform identity linking = personal data processing under GDPR; E18 (ERC-8004) stores reputation on-chain immutably. Tension not fully resolved — hybrid approach (off-chain mutable components + on-chain immutable attestation hashes) is emerging best practice.

5. **cheqd vs EAS**: E25 documents cheqd's own Cosmos-based attestation layer; E2 covers Ethereum-based EAS. No direct integration found between the two systems, but cheqd DSID can reference EAS attestations via cross-chain messaging (emerging, not production-proven).

6. **ERC-8004 adoption numbers**: E18 cites 24K first week and 100K+ by mid-Feb; RNWY guide cites 20K+ feedback entries (Base hosts 73.6%). Numbers are compatible (registrations ≫ active feedback entries — many exploratory registrations).
