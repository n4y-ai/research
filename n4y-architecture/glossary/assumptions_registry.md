# Assumptions Registry (Реестр допущений)

> **Версия:** 2.2 (13 эскалаций ESC-001..ESC-013 закрыты вердиктом APPROVE 2026-05-09)
> **Дата:** 2026-05-09
> **Краткое описание артефакта:** Канонический реестр продуктовых утверждений Logos/N4Y, на которых строится архитектура. Каждая запись фиксирует утверждение, его тип, статус, потребителей и известные конфликты. Обновляется при аудитах и публикациях измерений; в OI Resolution Pipeline пополняется applier'ом на шаге 12 (Phase 1) и Phase 0 audit applier'ом.
> **Изменено в v2.2 (2026-05-09):** 13 A-IDs (A31, A34, A49, A50, A51, A54, A55, A56, A58, A61, A62, A70, A72) переведены из `proposed-for-approval` в `committed` после пакетного APPROVE пользователя по ESC-001..ESC-013 (см. `main/reference/registry/oi-decisions-needed.md` → архивный раздел).
> **Изменено в v2.1 (2026-05-07):** применены результаты Phase 0 audit (см. `main/reference/clusters/phase0-audit/audit-report.md` + `apply-manifest.md`): 9× re-formulate, 2× re-type (A18, A19), 15× update-used-by, 2× deprecate (A9, A28), +44 новых записи (A29..A72) из reverse sweep по 29 финальным dim.
> **Изменено в v2.0 (2026-05-07):** добавлены колонки `Тип` (assumption / proposal / position) и `Статус` (committed / proposed-for-approval / deprecated). A1..A28 мигрированы с дефолтами `Тип=assumption`, `Статус=committed`.

---

## Формат записи

| Колонка | Описание |
|---------|----------|
| `#` | A-ID (сквозная нумерация A1, A2, ...; provisional A-NEW-N до commit) |
| `Тип` | `assumption` — техническое допущение / `proposal` — предложение по эволюции внешних артефактов или регуляции / `position` — продуктовая позиция |
| `Допущение` | Текст утверждения. Должен быть самодостаточным, читаемым без контекста. |
| `Статус` | `committed` — принято и в реестре / `proposed-for-approval` — PO предложил, ждёт buy-in пользователя/stakeholder; параллельно эмитится в `oi-decisions-needed.md` / `deprecated` — устарело, сохраняется для traceability |
| `Кто использует` | Список dim / артефактов / стратегий, опирающихся на это утверждение |
| `Потенциальные конфликты` | Известные противоречия с другими A-N, регуляторикой или внешним контекстом |

---

## Lifecycle (для OI Resolution Pipeline)

1. **Phase 0 audit** обнаруживает unregistered claims в финальных dim и регистрирует их с provisional A-NEW-N.
2. **Phase 1 шаг 4 (PO Brief):** PO эмитит provisional `A-NEW-N` в Section 7 `po-brief.md` с типизацией.
3. **Phase 1 шаг 8 (Draft Composer):** любой preview-блок, опирающийся на A-N, обязан содержать `[A-N]` / `[A-NEW-N]` reference.
4. **Phase 1 шаг 11 (PO Review) Section 7:** финальный mapping `A-NEW-N → A-N (assigned)` + статус.
5. **Phase 1 шаг 12 (Applier):** appendит новые A-N в этот реестр; preview-файлы с `A-NEW-N` → заменяются на `A-N`. Записи `proposed-for-approval` дублируются в `oi-decisions-needed.md`.
