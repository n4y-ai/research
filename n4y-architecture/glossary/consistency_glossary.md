# CONSISTENCY GLOSSARY (Canonical)

> **Версия:** 2.5 (L3/D01–D10 glossary sync: 8 terms added, 11 refs updated)  
> **Дата:** 2026-04-15  
> **Краткое описание артефакта:** Канонический глоссарий терминов, сокращений и допущений Logos/N4Y; аккумулятивно обновляется после аудитов. Актуальная спецификация — в `L1_D01`–`L3_D10`. 

---

## Термины

| Термин | Сокр. | Определение | Где встречается | Примечания |
|--------|-------|-------------|-----------------|------------|
| **Логос (Logos) — Персональный** |  | это персональный цифровой двойник субъекта (человека), основанный на технологиях искусственного интеллекта и способный к автономному функционированию в рамках делегированных ему прав от лица субъекта (например: заключать сделки, нести финансовую ответственность, накапливать капитал (в цифровом его проявлении), взаимодействовать с другими Логосами и т.д.) в управляемой цифровой децентрализованной экономической среде. | L1/D01; L3/D01 | Основная сущность системы. Привязан через PoP. 1 человек = 1 персональный Логос |
| **Логос (Logos) — Корпоративный** |  | Роль внутри юридического лица (не двойник самого юрлица). Владелец роли — организация (`Org DID`, верифицирован через KYC/AML/KYB, не PoP); роль имеет собственный `Corporate Logos DID` (controller = Org DID) и обращена к внешнему миру. Роль занимает (occupancy) личный Логос сотрудника через Employment/Role VC; одно юрлицо владеет N такими ролями. Ограниченная функциональность: не накапливает личную репутацию, права (ESq) определяются корпоративной лицензией и определением роли. | L1/D01 | Модель «организация → роль → исполнитель» (L1/D01 §8, OI-086). Отличать от персонального Логоса |
| **Decentralized Identifier** | DID | Глобально уникальный идентификатор, контролируемый субъектом, без зависимости от центрального реестра | L1/D01; L3/D01 | W3C standard, v1.1 Working Draft (янв 2026) |
| **Verifiable Credential** | VC | Криптографически подписанная аттестация от издателя в отношении субъекта | L1/D01; L1/D02 | W3C standard, v2.0 Recommendation (май 2025) |
| **Expert Skills** | ES | Единица специализации — зонтичный термин. Разделяется на ESq и ESc (см. ниже) | L1/D02 | Fix C-001: разделён на два чётких термина |
| **Expert Skill Quota** | ESq | Максимальный суммарный объём ES, который владелец может распределить между микроагентами. Определяется Human Credentials × Agent Capability multiplier. ESq_effective = ESq_base(human_creds) × capability_multiplier(agent_benchmark_VC). ESq и AGC — независимые ограничения | L1/D01; L1/D02; L1/D03; L1/D08 | Permission gate. Не конвертируется в AGC |
| **Expert Skill Cost** | ESc | Стоимость создания/поддержания конкретного микроагента в единицах ES. Определяется сложностью задачи и типом специализации | L1/D02; L1/D03; L1/D08 | При создании агента: списывается ESc из ESq-квоты |
| **Expert Skill Runtime** | ESr | Предложенный термин для обозначения фактических runtime-capabilities агента (измеряются benchmark scores), в отличие от ESq (квота владельца). [Phase 8] | L1/D02 | Предложенный рейнейм; формальный статус не принят |
| **Educational VC** |  | Верифицируемая аттестация формальной квалификации человека-владельца Логоса: Open Badges 3.0 / EDCL-совместимый формат, выданная аккредитованным учреждением-эмитентом, содержащая ESCO-aligned competency claims, нормированные через EQF уровни. Формирует `ESq_base` в Authorization Track. | L1/D02 | Кандидат на добавление из L1/D02 v4.0; формирует Authorization Track |
| **AgentCredits** | AGC | Стабильная операционная валюта, привязанная к фиату (1 AGC ≈ 1 USD). Классифицируется как EMT по MiCA Title IV (L2/D08 §3.1). Резервные требования: ≥100% в fiat/гособлигациях (MiCA Art. 54). Supplementary Qi stability buffer: governance-tunable, размер 5-15% AGC float, threshold ±0.5-2%, см. L2/D05 §2.2. [A3][A47] Эмиссия: только через fiat gateway (USD → mint AGC 1:1); burn: redemption (AGC → USD) | L1/D03; L1/D06; L1/D08; L2/D05 | Operations Layer. MiCA EMT |
| **Qi Energy** | Qi | Базовый value & governance asset экосистемы, фиксированное предложение 333M токенов (предварительно). Классификация по MiCA: **OCA (Other Crypto-Asset)** canonical per L2/D08 §3.2 и L2/D02 §6.3. Qi НЕ является primary collateral для AGC [A47]; ценность формируется через revenue share (40% дохода платформы → stakers), scarcity (fixed supply + staking locks) и governance premium (veQi). MiFID II boundary — medium-priority monitoring (OI-059). Полное описание dual-token mechanics — `→ L2/D05 §2`. | L1/D03; L2/D08; L2/D02; L2/D05 | Value & Governance Layer. MiCA OCA (canonical) |
| **Микроагент** |  | Специализированная единица Логоса с ограниченным набором умений и разрешений для конкретной области задач | L1/D02; L1/D03 | Часть микроагентной архитектуры |
| **Proof-of-Personhood** | PoP | Механизм верификации уникальности человека (Sybil-resistance) | L1/D01 | Worldcoin, BrightID, HCO |
| **Zero-Knowledge Proof** | ZKP | Криптографический протокол для доказательства утверждения без раскрытия базовой информации | L1/D01 | Используется для selective disclosure в VC |
| **Trust Registry** |  | On-chain реестр верифицированных агентов с attestations безопасности и подлинности | L1/D01 | Аналог: SingularityNET + Privado ID |
| **Agent Card** |  | JSON-метаданные агента: идентичность, capabilities, endpoint, аутентификация | L1/D01; L1/D05 | Стандарт A2A protocol (Google) |
| **Resource Marketplace** |  | Площадка для торговли вычислительными ресурсами между Логосами и поставщиками | L1/D03 | Аукционный механизм |
| **Trusted Execution Environment** | TEE | Защищённый анклав для конфиденциальных вычислений на чужом hardware | L1/D03 | Intel SGX, AMD SEV. Akash планирует Q2 2026 |
| **Open Badges 3.0** |  | Стандарт 1EdTech для цифровых achievement credentials, совместимый с W3C VC | L1/D02 | Final Release v1.4.1 (ноябрь 2025) |
| **European Skills/Competences framework** | ESCO | Таксономия навыков и компетенций. Версия v1.2 (актуальная): 3,039 occupations, 13,939 skills, 28 languages; REST API: `ec.europa.eu/esco/api` | L1/D02 | Рекомендован как основа для ES-онтологии. [Phase 8]: обновлена версия и параметры |
| **Delegation VC** |  | Верифицируемая аттестация, фиксирующая scope делегированных прав от субъекта к Логосу. Каноническая структура (Д8 §4.2): identity, autonomy_config (LOA), scope (domains, AGC limits, forbidden_actions), hitl_thresholds, escalation, revocation | L1/D01; L1/D06; L1/D07; L3/D04 | Связывает DID человека с DID Логоса. Юридический инструмент (L1/D06 §6, canonical owner) |
| **Agent Capability VC** |  | Верифицируемая аттестация фактических способностей агента (результаты benchmarks, safety audit). Holder = Логос (не человек). Влияет на capability_multiplier в формуле ESq | L1/D02 | Отделяет компетенцию человека от capabilities агента |
| **Human Challenge Oracle** | HCO | Механизм непрерывной верификации человечности через time-bound, криптографически привязанные challenges. Persistent Sybil resistance | L1/D01 | Дополняет PoP |
| **Almanac** |  | On-chain реестр (Fetch.ai, Cosmos-based) для trustless discovery. Используется как для обнаружения агентов (identity), так и для обнаружения ресурсов (marketplace) | L1/D01; L1/D03; L1/D05 | Единый реестр с двумя функциями |
| **Resource Router** |  | Компонент Логоса для автоматического выбора поставщика ресурсов по критериям (цена, latency, privacy, SLA) | L1/D03; L2/D03 | Предложен как часть архитектуры Логоса |
| **Burn-Mint Equilibrium** |  | Модель токеномики: токен сжигается при использовании и минтится для стабилизации цены. Используется в Akash Network как внешний аналог; в N4Y.AI применим только к Qi-value layer (`→ L2/D05 §2.5`), НЕ к AGC [A47] | L1/D03; L2/D05 | Внешний аналог (Akash); AGC использует reserve/redemption/peg-механику, а не BME [A47] |
| **Orchestrator** |  | Центральный компонент Логоса: Task Router + Planner + Context Manager + Execution Engine. Управляет декомпозицией, маршрутизацией и исполнением задач микроагентов | L1/D04 | Ядро функциональной архитектуры. [OI-098: section ref updated] |
| **Model Context Protocol** | MCP | Open-source стандарт (Anthropic, 2024) для подключения AI к внешним системам. Scope: agent-to-tool (НЕ agent-to-agent). Спецификация 2025-11-25 | L1/D04; L1/D05 | «USB-C для AI» |
| **Agent-to-Agent Protocol** | A2A | Open standard (Google, апрель 2025) для inter-agent communication. Компоненты: Agent Card, Task lifecycle, Messages, Parts. **Текущая версия: v1.0.0 (март 2026)**: gRPC transport, JWS-signed Agent Cards, 150+ orgs, AAIF governance. (Предыдущая ссылка v0.3.0 устарела.) [OI-101, OI-135 — closed] | L1/D01; L1/D04; L1/D05; L2/D04; L3/D01; L3/D02 | Scope: agent-to-agent (НЕ agent-to-tool) [A10] |
| **DIDComm** |  | Secure messaging protocol на базе DID. E2E encrypted, asynchronous. Используется для security layer поверх A2A | L1/D05; L3/D01 | DID-based authentication |
| **Tool Manifest** |  | Декларативная конфигурация микроагента: список MCP-серверов, разрешённые/запрещённые инструменты, лимиты | L1/D04 | Часть MCP-интеграции. [OI-098: section ref updated] |
| **HITL Gate** |  | Точка в execution flow, где требуется подтверждение человека-владельца перед продолжением. Активация зависит от LOA (Д8 §4.1): LOA-1 — всегда, LOA-4 — только scope violation. См. C-029 для уточнения | L1/D04; L1/D07 | Human-in-the-loop. [OI-098: section ref updated] |
| **Execution Trace** |  | Полная трассировка выполнения задачи: план, шаги, tool calls, решения, стоимость | L1/D04 | Observability + audit trail. [OI-098: section ref updated] |
| **Structured Handoff** |  | Intra-Logos протокол: надмножество A2A Message + оркестрационные поля (parent_task_id, constraints, version) | L1/D04; L1/D05 | При inter-Logos — сворачивается до A2A Message. [OI-098: D04 section ref updated; OI-097: D05 §4.4.1 sub-ref was invalid] |
| **Saga Pattern** |  | Паттерн управления распределёнными транзакциями через компенсирующие действия при отказах | L1/D04 | Error handling. [OI-098: section ref updated] |
| **Performative** |  | Тип речевого акта в сообщении: request, inform, confirm, reject и др. На основе FIPA ACL | L3/D02; L1/D05 | Семантика сообщений |
| **E-Money Token** | EMT | Криптоактив, привязанный к фиатной валюте. По MiCA (2023/1114) Title IV требует лицензированного эмитента (EMI) и резервов ≥100% в high-quality liquid assets (fiat/гособлигации). AGC классифицируется как EMT (L2/D08 §3.1) | L1/D06; L2/D08 | MiCA-specific |
| **Asset-Referenced Token** | ART | Криптоактив, привязанный к корзине активов (MiCA Title III). Требует авторизации, white paper и reserve of assets. В архитектуре N4Y.AI: AGC не является ART (обеспечен fiat, не корзиной); Qi не является ART (не привязан к корзине активов) | L1/D06 | MiCA-specific |
| **Qualified Electronic Attestation of Attributes** | QEAA | Криптографически верифицируемая аттестация по eIDAS 2.0 с юридической силой в ЕС | L1/D06; L2/D08 | eIDAS 2.0 |
| **Qualified Electronic Signature** | QES | Электронная подпись с юридической силой, эквивалентной собственноручной, по eIDAS 2.0 | L1/D06 | eIDAS 2.0 |
| **Data Protection Impact Assessment** | DPIA | Обязательная оценка воздействия на защиту данных для high-risk обработки по GDPR Art. 35. Также обязателен для deployer high-risk AI по AI Act Art. 26(9) | L1/D06; L2/D08 | GDPR + AI Act |
| **Fundamental Rights Impact Assessment** | FRIA | Обязательная оценка воздействия на фундаментальные права, выполняемая deployer высокорисковых AI-систем по EU AI Act Art. 27(1) Annex III categories (biometric identification, critical infrastructure, education, employment, essential services, law enforcement, migration, justice). Отличается от DPIA по правовой основе, исполнителю и содержанию (AI Act vs GDPR); может координироваться с DPIA, но остаётся самостоятельным документом. [A82][A83] | L2/D08 | EU AI Act Regulation 2024/1689 Art. 27 |
| **Strict liability** |  | Ответственность без вины: оператор отвечает за ущерб от AI-системы независимо от умысла. Применяется к high-risk AI в ЕС через PLD (Directive 2024/2853, с 09.12.2026). Примечание: AILD отозван 11.02.2025 | L1/D06 | EU Liability Framework (PLD) |
| **Level of Autonomy** | LOA | Шкала от LOA-1 (исполнитель) до LOA-5 (доверенный), определяющая степень самостоятельности Логоса. Задаётся владельцем в Delegation VC. Расширяет L1-L4 из Д4 §4.7.2 (C-024) | L1/D07 | Каноническая шкала автономии |
| **loa_ceiling** |  | Максимальный LOA, который владелец разрешает данному экземпляру Логоса через Binding VC. Precedence rule: `LOA_effective = min(loa_ceiling, domain_override.LOA)` — loa_ceiling всегда ограничивает; domain_overrides не могут превышать loa_ceiling. | L1/D07 | Monotonic attenuation invariant |
| **Non-delegable core** |  | Набор действий, запрещённых при любом LOA: (1) изменение идентичности, (2) юридически обязывающие решения, (3) перевод Qi, (4) повышение LOA, (5) репликация, (6) нарушение GDPR Art.22 / EU AI Act Art.14 safeguards (automated decision-making rights, human review on request). Governance non-delegable core (A26): голосование, делегирование, участие в выборах SC — только человек [L1/D07 v4.0 — OI-116: cat.6 added] | L1/D07; L2/D09 | Platform-level, non-overridable. OI-063: governance finalization pending (5 vs 6 items). |
| **Emergency brake** |  | Мгновенное снижение автономии до LOA-1 с приостановкой миссий. Три источника: владелец, платформа, smart contract | L1/D07 | — |
| **Earned autonomy** |  | Принцип повышения LOA через accumulated track record + явное решение владельца | L1/D07 | — |
| **Domain-specific LOA** |  | Разные LOA для разных доменов одного Логоса (travel=LOA-4, finance=LOA-2) через domain_overrides в Delegation VC | L1/D07 | — |
| **Task Router** |  | Подкомпонент Orchestrator: классифицирует входящий запрос, оценивает сложность и budget/quality envelope, выбирает класс задачи A–D и стартовый execution path. Не владеет LOA policy (→ L1_D08 §1–§2) | L1/D04 | Введён D04 v4.0 dim glossary |
| **Planner** |  | Подкомпонент Orchestrator: строит DAG задачи, определяет dependency edges, условия параллелизма, критерии re-plan и verification checkpoints. Не владеет ESq/ESc semantics (→ L1_D02 §5.5) | L1/D04 | Введён D04 v4.0 dim glossary |
| **Context Manager** |  | Подкомпонент Orchestrator: удерживает thread state, summaries, episodic/semantic abstractions и cross-session continuity (xMemory-style hierarchy). Не владеет physical storage substrate (→ L1_D03 §4–§7) | L1/D04 | Введён D04 v4.0 dim glossary. A22: Reflection Engine = расширение Context Manager |
| **Execution Engine** |  | Подкомпонент Orchestrator: вызывает MCP tools и sub-agents, контролирует статус, retries, compensations, audit trail и пишет Execution Trace. Не владеет Budget Controller (→ L1_D09 §4.2) | L1/D04 | Введён D04 v4.0 dim glossary |
| **Budget Controller** |  | Компонент Логоса для управления AGC-бюджетом: Allocation Engine, Spending Monitor, Earning Tracker, Cost Estimator, Reporting. Работает наряду с Orchestrator (Д4). C-031: интеграция с Д4 не специфицирована | L1/D08 | Обязательный компонент (A17) |
| **Cost Estimator** |  | Подкомпонент Budget Controller, оценивающий стоимость задачи перед dispatch (LLM tokens × rate + tool calls × rate) | L1/D08 | — |
| **Escrow (Smart Contract)** |  | On-chain контракт для безопасного хранения AGC до выполнения условий. Поддерживает time-lock, milestones, dispute routing. Правовая квалификация — open (Д7 §6.10, C-026). Требует механизм kill switch по EU Data Act Art. 36 | L1/D08 | — |
| **State channel** |  | Off-chain механизм для агрегации микротранзакций с периодическим on-chain settlement. Снижает gas costs | L2/D03 | Рекомендован для tool call микроплатежей |
| **Dual constraint** |  | Принцип: действие Логоса требует (A) ESq ≥ ESc (permission gate) AND (B) AGC_available ≥ expected_cost + protected_reserve (payment gate). Независимые, не конвертируемые ограничения. Оба gate должны быть пройдены одновременно. [L1/D08 §3.1 — OI-121: protected_reserve добавлен] | L1/D08; L1/D01; L1/D02; L1/D03 | Fix C-001/C-005 |
| **Call for Proposals** | cfp | FIPA-перформатив: запрос конкурентных предложений от других Логосов. Инициирует ценообразование inter-Logos | L1/D05; L1/D08; L2/D06 | Часть FIPA ACL |
| **Performance VC** |  | Верифицируемая аттестация результатов деятельности Логоса. 5 типов: Task Completion, Peer Feedback, Benchmark, Safety Audit, Incident. Основная единица репутационных данных. **C-036**: границы с Agent Capability VC (Д2) требуют уточнения | L1/D09 | Umbrella type |
| **Reputation Score** |  | Мультикомпонентная числовая оценка (0–100) надёжности и качества Логоса. 5 компонентов: TP, PF, CC, ER, DE. Domain-specific. Weights governance-tunable (A20) | L1/D09 | Совместима с ERC-8004 |
| **Reputation Tier** |  | Категоризация Логоса по уровню Reputation Score: Unrated → Bronze (1–30) → Silver (31–55) → Gold (56–75) → Platinum (76–90) → Diamond (91–100). Визуализируется через Reputation SBT | L1/D09; L3/D01 | 6 уровней |
| **Reputation Stake** |  | AGC-депозит нового Логоса как залог качества для bootstrap. Возвращается при успешном завершении первых N задач, конфискуется при failure | L1/D09 | Cold start mechanism |
| **Reputation SBT** |  | Non-transferable token (ERC-5192) на DID Логоса, визуально отображающий текущий Reputation Tier. Публикуется в Agent Card | L1/D09 | Soulbound Token |
| **ERC-5192** |  | Ethereum стандарт non-transferable (soulbound) token semantics. Используется в N4Y.AI как tier-badge layer: Reputation SBT реализует ERC-5192 для визуализации текущего Reputation Tier агента поверх score/VC architecture. Non-transferable — tier badge привязан к конкретному DID Логоса. | L1/D09 | [L1/D09 v4.0 — OI-108 audit] |
| **Trust Graph** |  | Контекстный граф доверия, интерпретирующий credential pathways, иерархии доверия и relationship-specific trust поверх простого registry score.
